# Audit Sampling & Risk Assessment Tool

**[▶ Live demo](https://ps-audit-tool.streamlit.app/)**: fictional utility and
synthetic ledgers, one-click sign-in (runs with `AUDIT_TOOL_DEMO=1`; resets on
restart).

A local, single-machine web tool for the statutory audit of a regulated
electricity transmission utility: **SA 315** risk assessment, **SA 530**
statistical sampling, **SA 505** balance confirmations, **SA 230** audit
documentation, and regulated-revenue cross-checks against the State
Electricity Regulatory Commission's (**SERC**) MYT tariff order.
All client data stays on this machine.

> **About this portfolio edition.** The client in every example, test and
> manual is *Kestrel Transmission Ltd*, a **fictional** utility, and all
> ledger data is synthetic (generated by `demo/generate_demo_data.py`, with
> planted audit exceptions to find). The hosted demo runs with
> `AUDIT_TOOL_DEMO=1`: a throwaway database, a pre-built engagement and
> one-click sign-in. Manuals: `docs/Kestrel_Audit_Tool_Manual.pdf` and
> `docs/Kestrel_Audit_Tool_User_Guide.pdf`.

## Quick start

```bat
run_tool.bat
```

(or `.venv\Scripts\python -m streamlit run app.py`). The browser opens at
`http://localhost:8501`. On first run the tool asks you to create the
**Partner (administrator)** account; passwords are stored as scrypt hashes
in the local SQLite database (`data\audit_tool.db`).

To try the tool before loading client data, generate the synthetic demo
dataset (~25k SAP-format ledger rows for FY2025-26):

```bat
.venv\Scripts\python demo\generate_demo_data.py
```

then import `demo\output\demo_sap_ledger_fy2026.xlsx` and
`demo_trial_balance_fy2026.xlsx` in step 2, and use
`demo_serc_order_fy2026.xlsx` (or type the values) in step 7.

## Deployment & sharing

Running `run_tool.bat` (or the **Kestrel Transmission Audit Tool** Desktop shortcut)
**is** the deployment: the app serves at `http://localhost:8501` and, per
`.streamlit\config.toml`, is reachable only from this machine.

- **Colleagues on a trusted office network**: change `address = "localhost"`
  to `address = "0.0.0.0"` in `.streamlit\config.toml`, restart, and share
  `http://<your-ip>:8501` (shown in the terminal as "Network URL"). They get
  the same login page; allow the Windows Firewall prompt once. Note SQLite +
  Streamlit is fine for a few sequential users, not for heavy concurrent use.
- **Streamlit Community Cloud (the "Deploy" button)**: deliberately hidden
  and **not recommended for this tool** - it would (a) upload client
  financial data to third-party public-cloud servers, and (b) lose all work,
  because the cloud container's disk is wiped on every restart, deleting the
  SQLite database and the SA 230 audit trail. It also requires the code to
  be pushed to GitHub.
- **Firm-wide server deployment** (proper multi-user, HTTPS, backups) is the
  v2 path noted below - run it on a machine the firm controls, never on a
  free public cloud, given client confidentiality.
- Pushing the **code** (never `data\`) to a **private** GitHub repository is
  fine as version-control backup; that is unrelated to hosting the app.

## Workflow (sidebar steps)

1. **Engagement & materiality** — create the engagement (an engagement
   **master seed** is generated once and printed on every report; all sample
   seeds derive from it) and complete the SA 320 worksheet: benchmark ->
   overall materiality -> performance materiality -> individually-significant
   cutoff.
2. **Data import** — upload the ledger (Excel/CSV). Column mapping is
   auto-guessed for SAP FAGLL03/FBL3N-style exports and editable; mappings can
   be saved as reusable templates. Handles SAP trailing-sign negatives
   (`1.234,56-`), Indian and European number formats, bracketed negatives,
   footer rows. Every file's SHA-256 is recorded. Import the TB to get the
   per-account **ledger-vs-TB reconciliation**.
3. **Categorize** — priority-ordered rules (account prefix/range/regex or
   narration keywords) map transactions to audit categories. Resolve the
   Uncategorized bucket before analysis.
4. **Risk configuration** — per-category assigned weights (1–10, defaults per
   the engagement risk profile: electricity income 10, spares 9, deferred tax
   9, R&M 8 with a hybrid cutoff, overheads 3 ...), control/complexity
   factors, cutoffs, preferred methods, and the strategy thresholds
   (>= 8 -> 100% or hybrid; 4–8 -> stratified/MUS; < 4 -> small random).
   Every change requires a reason and is logged. (Manager+)
5. **Analysis run** — scores each population (assigned weight prevails;
   computed factor score shown alongside), routes items to the 100% list
   (full categories, hybrid items >= cutoff, individually significant items,
   contra entries) and stamps anomaly flags (duplicates, round sums,
   period-end, weekend, keywords, zero amounts).
6. **Sampling** — per population: MUS, stratified, systematic or simple
   random. Sample sizes per SA 530: exact-binomial attribute sizes
   (reproduces the published tables: 95%/5%/0% -> 59) and MUS
   `n = BV x RF / (TM − EM x EF)` with Poisson reliability factors computed
   exactly (3.00 / 4.75 / 6.30 at 95%). Selections are reproducible: numpy
   PCG64, documented seed, canonical sort (date, doc no, row id), population
   SHA-256. Regeneration supersedes the old sample and requires a logged
   justification (Manager+).
7. **SERC reconciliation** — approved ATC / wheeling / true-up / incentive
   vs booked electricity income: monthly variances against a threshold and
   the annual tie-out.
8. **Balance confirmations (SA 505)** — per area (receivables, payables,
   banks, loans & advances): import the party-wise SAP balance export and the
   balances confirmed in writing by the parties (both with flexible column
   mapping), match on party code (SAP leading zeros ignored) with a
   normalized-name fallback, and classify every party: Agreed / Exception
   (SA 505.14) / No response (SA 505.12 alternative procedures) / Not in
   books (completeness signal). Coverage and response statistics, a
   mirror-image sign detector, per-party conclusions, working-paper CSV.
9. **Results & evaluation** — record Pass/Exception and audited values
   in-app, or re-import the completed Excel pack (a hidden `_meta` sheet maps
   tabs to samples). Evaluation: MUS Stringer bound (projected misstatement +
   basic precision + incremental allowance = UML vs TM; understatements
   reported separately), ratio & difference projections, achieved upper
   deviation limit.
10. **Reports & export** — Excel workpaper pack (cover & sign-off,
    materiality, risk matrix, 100% list, sample tabs with parameter boxes,
    evaluation, SERC recon, confirmation tabs, exceptions, audit trail) and
    the PDF sampling memorandum; CSV extracts. Copies are archived under
    `data\exports\`.
11. **Admin & audit trail** — users/roles (Partner), and the append-only
    SA 230 log (every import, config change with reason, generation seed,
    export). The application has no code path that updates or deletes log
    rows.

## Standards mapping

- **SA 315 (Revised)** — factor-based risk scoring at the population level;
  prior-year qualifications (spares/Ind AS 16, R&M, deferred tax) and
  regulatory dependence drive the default weights.
- **SA 320** — materiality worksheet; the individually-significant cutoff
  feeds automatic 100% routing.
- **SA 530** — statistically valid sizes (exact binomial / Poisson RF),
  transparent reproducible selection, projection of misstatements and
  conclusion vs tolerable misstatement. (The definition cited is
  SA 530(5)(a); PCAOB AS 2315 is the US analogue.)
- **SA 230 / SQC 1** — append-only audit trail, seeds and dataset hashes on
  every report, archived exports.
- **Ind AS 115** (revenue), **Ind AS 109** (interest income), **Ind AS 16**
  (capital spares) — referenced in category notes and the memorandum.

## Scope notes (v1)

- Single machine, one user at a time (SQLite + local Streamlit).
- No MFA; no at-rest database encryption — rely on OS-level protection
  (BitLocker) and physical control of the laptop. SQLCipher is a candidate
  for a later version.
- SERC tariff orders are entered manually or via a simple parameter file;
  PDF parsing of orders is out of scope.
- `data\` (client data, DB, exports) is gitignored — never commit client
  data.

**Professional-judgment disclaimer**: the tool computes and documents; the
auditor decides. Sample sizes, risk weights and conclusions remain matters
of professional judgment under the SAs; verify parameters against the
current ICAI pronouncements and the engagement's circumstances.
